# 0008. 壞資料剔除並回報，不讓整頁失敗

- 狀態：已採用
- 日期：2026-11-18

## 背景

資料來源（今天是 mock，日後是後端 API）可能出現格式錯誤的商品，例如價格為負、缺少圖片。若直接渲染，可能顯示錯誤價格或造成元件例外；若整批視為失敗，一筆壞資料就會讓整個首頁顯示錯誤。

## 決策

- `data-access/validation.ts` 的 `productProblems()` 列出一筆商品的所有問題，空陣列代表可安全渲染。
- `MockCatalogApi` 載入資料後驗證一次：壞資料從商品清單與推薦清單中剔除，並以 `level: 'warn'`、`name: 'InvalidCatalogRecord'` 送到 `LOG_SINK`，附上問題清單。
- 首頁商品列引用到已剔除的 id 時，`getProductsByIds` 本來就會略過，畫面只是少一張卡。
- 同一套驗證日後直接套用在 `HttpCatalogApi` 的回應上。

## 影響

- 好處：局部壞資料只造成局部缺漏，使用者仍可正常購物；問題會被記錄，不會默默消失。
- 代價：被剔除的商品對使用者「消失」，必須依賴 log 監控才會被發現，因此回報是這個決策不可省略的一部分。
